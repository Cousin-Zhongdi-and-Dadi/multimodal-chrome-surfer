## 1. 项目背景与目标

### 1.1 背景

浏览器是人类获取信息和完成数字任务的重要入口。真实网页环境复杂、动态且经常出现意外情况。人类在操作浏览器时，会同时利用文字、页面结构和视觉信息，并根据页面变化不断调整行为。

本项目希望构建一个多模态浏览器自主操作助手，能够根据自然语言指令，自主使用浏览器完成复杂任务。系统应当像人一样理解和操作网页，而不是为少数固定网站编写预设脚本。

### 1.2 目标

- 用户通过自然语言下达任务。
- Agent 自主完成浏览器感知、规划、执行、验证和结果整理。
- 支持复杂、动态、长流程网页任务。
- 支持任务中断、人工确认和异常恢复。
- 通过技能/记忆沉淀，逐步提升重复任务的效率和成功率。

### 1.3 示例任务

- 在 B 站找到“影视飓风”最新发布的视频，并跳转到视频的 2 分 30 秒位置。
- 在 Percy Liang 的 Google Scholar 页面中，找到他在 2023 年发表的被引次数最多的论文，并打开对应论文页面。
- 在问卷页面根据给定信息自动填写复杂表单。
- 在多个页面之间搜索、筛选和整合信息，并完成后续操作。

## 2. 方案概述与边界

### 2.1 方案概述

采用“Chrome 插件 + 本地 Generic Agent 服务”的混合架构。

- Chrome 插件负责浏览器感知与控制、用户交互界面、页面状态采集和动作执行。
- 本地 Generic Agent 服务负责任务规划、推理、记忆、技能沉淀和 LLM 调用。
- 两者通过标准化消息协议通信。

### 2.2 职责划分

| 模块 | 主要职责 |
| --- | --- |
| Chrome 插件 | 标签页管理、页面快照、DOM 操作、表单填写、截图、用户确认、页面变化监控 |
| 本地 Generic Agent 服务 | Agent Loop、任务规划、工具调度、LLM 调用、记忆管理、SOP 技能沉淀、浏览器动作决策 |
| 通信层 | 连接管理、消息路由、超时处理、重连恢复、状态同步 |

### 2.3 v1 边界

- 先支持 Windows + Chrome/Chromium。
- 以本地运行模式为主。
- 不直接实现云端多租户。
- 不追求一次性覆盖所有网站，而是通过“通用能力 + 可沉淀技能”逐步扩展。
- 本阶段只形成开发计划文档，不修改 `GenericAgent/` 源码。

### 3.1 Chrome 插件组件

- Service Worker：处理插件生命周期、消息路由、Native Messaging 连接、标签页事件。
- Side Panel：任务输入、Agent 输出、人工确认、停止/恢复操作。
- Content Scripts：负责页面快照、DOM 读取、动作执行、页面变化监控。
- Offscreen Document：仅在需要长时间保活或执行轮询任务时启用。
- Native Messaging Client：与本地 Generic Agent 服务通信。

### 3.2 本地 Generic Agent 服务组件

- Agent Loop：执行“感知 -> 规划 -> 执行 -> 验证 -> 记忆”循环。
- 工具层：在现有 `code_run`、`file_read`、`file_write`、`file_patch`、`web_scan`、`web_execute_js` 等工具基础上，新增结构化浏览器动作工具。
- 记忆层：继续使用 GenericAgent 的分层记忆与 SOP 技能机制。
- LLM Client：负责模型调用和上下文管理。
- Browser Bridge：维护与 Chrome 插件的连接，统一处理请求、响应、超时和重连。

### 3.3 通信方式

- 目标架构优先采用 Native Messaging。
- MVP 阶段可先复用 GenericAgent 现有的 `TMWebDriver` 本地服务作为过渡。
- 通信消息建议采用 JSON，按请求/响应/事件三类组织。

## 4. 业务实现流程

### 4.1 端到端流程

1. 用户在 Side Panel 输入自然语言任务。
2. Chrome 插件将任务发送给本地 Generic Agent 服务。
3. Agent 解析任务目标，制定执行计划。
4. Agent 请求浏览器感知：
   - 标签页列表；
   - 当前页面结构化摘要；
   - 可见元素、表单字段、按钮和链接；
   - 页面加载状态和异常信息。
5. Agent 根据感知结果生成下一步动作。
6. 动作类型包括：
   - 点击；
   - 输入文本；
   - 滚动；
   - 切换标签页；
   - 打开 URL；
   - 等待页面变化；
   - 执行受控 JavaScript；
   - 截图。
7. Chrome 插件执行动作，并返回执行结果和页面变化。
8. Agent 验证动作结果，判断是否需要重试、修正计划或请求用户确认。
9. Agent 持续循环，直到任务完成、用户停止或触发异常退出。
10. 任务完成后，Agent 更新工作记忆和长期技能/SOP。

### 4.2 任务状态流转

```text
新任务
  → 规划
  → 浏览器感知
  → 生成动作
  → 插件执行
  → 结果校验
  → 成功/失败/需确认
       │       │       │
       │       │       └── ask_user
       │       └── 重试或修正计划
       └── 更新 checkpoint / 继续下一动作
            → 任务完成
            → 更新长期记忆/SOP
```

## 5. 技术要点

### 5.1 Chrome Manifest V3 与 Service Worker

- 插件必须使用 Manifest V3。
- Service Worker 在 30 秒无活动后可能被终止，不能依赖进程内全局变量保存长任务状态。
- 重要状态必须持久化到 `chrome.storage` 或本地 Generic Agent 服务。
- 长任务可通过活跃 WebSocket、`chrome.debugger`、offscreen document 或 Native Messaging 保活。
- 事件驱动设计，避免长时间阻塞 Service Worker。

### 5.2 Side Panel 交互

- 使用 Side Panel 作为主要用户界面。
- 展示任务输入框、流式输出、状态提示、人工确认按钮和停止/恢复控件。
- Side Panel 不承担核心 Agent Loop，只负责 UI 和消息转发。

### 5.3 Content Script 与执行世界

- 默认 Content Script 运行在 ISOLATED world，适合 DOM 读取和常规操作。
- 需要访问页面 JavaScript 对象时，使用 MAIN world 或 User Scripts API。
- MAIN world 执行存在被页面读取或篡改的风险，只在必要时使用。
- 通用操作优先封装为结构化动作，减少任意 JS 执行。

### 5.4 浏览器控制 API

- `chrome.tabs`：标签页查询、创建、切换和关闭。
- `chrome.scripting`：向指定标签页注入脚本，支持 ISOLATED/MAIN world。
- `chrome.debugger`：在普通脚本无法完成时，使用 CDP 作为 fallback。
- `chrome.storage`：保存任务状态、配置和轻量缓存。
- `chrome.alarms`：定时轮询或保活。

### 5.5 Native Messaging 消息协议

建议的消息类型：

| 类型 | 方向 | 说明 |
| --- | --- | --- |
| `task.start` | 插件 → Agent | 开始新任务 |
| `task.stop` | 插件 → Agent | 停止当前任务 |
| `agent.output` | Agent → 插件 | 流式输出和状态 |
| `browser.list_tabs` | Agent → 插件 | 获取标签页列表 |
| `browser.snapshot` | Agent → 插件 | 获取页面结构化摘要 |
| `browser.action` | Agent → 插件 | 执行浏览器动作 |
| `browser.result` | 插件 → Agent | 返回动作执行结果 |
| `agent.ask_user` | Agent → 插件 | 请求用户确认 |
| `user.answer` | 插件 → Agent | 用户答复 |

### 5.6 Generic Agent 工具层扩展

- 保留 GenericAgent 原有核心工具：
  - `code_run`
  - `file_read`
  - `file_write`
  - `file_patch`
  - `web_scan`
  - `web_execute_js`
  - `ask_user`
  - `update_working_checkpoint`
  - `start_long_term_update`
- 新增或封装结构化浏览器工具：
  - `browser_list_tabs`
  - `browser_get_snapshot`
  - `browser_click`
  - `browser_type`
  - `browser_fill_form`
  - `browser_scroll`
  - `browser_screenshot`
  - `browser_wait_for_change`

### 5.7 页面感知优化

- 对 HTML 做简化和 token 压缩。
- 识别主内容区域、列表、弹窗和浮层。
- 过滤隐藏元素、不可见元素和无关脚本/样式。
- 处理 Shadow DOM、iframe、动态列表和懒加载内容。
- 输出结构化摘要，而不是每次全量 HTML。

### 5.8 动作执行可靠性

- 点击和输入优先使用可信事件。
- 必要时通过 CDP 执行输入事件，提升兼容性。
- 每次动作后采集页面变化。
- 对无变化、弹窗、跳转、刷新等结果进行区分。
- 对失败动作支持自动重试或人工确认。

### 5.9 权限与安全

- 遵循最小权限原则。
- 仅申请实现功能所必需的权限。
- 避免无条件申请 `debugger`，仅在确实需要时使用。
- API Key 不写入插件公开代码或日志。
- 用户任务数据和页面数据默认只在本机处理。
- 文档、日志和错误信息不得包含真实密钥或敏感 Cookie。

## 6. 实现难点分析

| 难点 | 说明 | 应对方向 |
| --- | --- | --- |
| MV3 后台非持久化 | Service Worker 可能随时被终止 | 状态持久化；任务状态放本地 Agent；必要时 offscreen/Native Messaging 保活 |
| SPA 动态 DOM | 内容异步加载，元素经常变化 | 动作后等待和监控；结构化快照；基于状态而非固定 XPath |
| 弹窗与页面跳转 | 点击后可能打开新标签页或刷新 | 监听 `tabs.onCreated` 和页面变化；返回新标签页信息 |
| 登录态和验证码 | 需要登录或出现人机验证 | 保留真实浏览器会话；触发 `ask_user`，不盲目绕过验证码 |
| 动作结果不确定 | 点击后未必产生预期变化 | 执行—观察—验证—重试闭环；页面变化 diff |
| Token 成本高 | 复杂页面全量 HTML 过大 | 页面摘要、列表截断、文本模式、局部 DOM 查询 |
| 插件与本地服务断连 | 本地进程重启、浏览器重启、连接超时 | 心跳、重连、任务 checkpoint、幂等消息 |
| LLM API 直连受限 | 浏览器直连可能遇到 CORS、密钥安全和供应商限制 | LLM 调用留在本地 Agent 服务；插件不直连模型 API |
| 通用性与固定脚本平衡 | 纯通用脚本成功率低，纯固定脚本不可扩展 | 结构化浏览器工具 + 少量受控 JS 逃生舱 + SOP 技能沉淀 |

## 7. 关键任务流程示例

### 7.1 B 站“影视飓风”最新视频跳转到 2:30

1. Agent 获取当前浏览器标签页列表。
2. 如果已有 B 站相关标签页，优先复用；否则打开 B 站。
3. 获取页面快照，判断当前页面是首页、搜索页还是空间页。
4. 执行搜索或进入“影视飓风”UP 主空间。
5. 获取视频列表结构化摘要，筛选最新视频。
6. 点击最新视频，等待视频页加载。
7. 通过受控 JavaScript 或播放器对象将播放进度设置为 150 秒。
8. 读取当前播放时间，确认已经跳转到 2:30。
9. 如失败，尝试点击播放器时间轴或再次调用播放器 API。
10. 完成后更新 checkpoint，并沉淀 B 站视频定位技能。

### 7.2 Google Scholar 2023 年被引最多论文并打开

1. 获取或打开 Google Scholar 页面。
2. 搜索 Percy Liang。
3. 获取论文列表结构化摘要，包含标题、年份、引用数、链接。
4. 筛选 2023 年论文，并按引用数排序。
5. 选择被引最多的论文。
6. 点击论文链接，等待新标签页或页面跳转。
7. 确认目标页面已经打开，并返回最终 URL 和标题。
8. 如页面出现反自动化或验证码，优先人工确认。

### 7.3 复杂表单自动填写

1. 用户提供待填写信息或信息源。
2. Agent 获取表单页面摘要，识别字段类型。
3. 根据 label、placeholder、name、DOM 结构匹配字段。
4. 使用结构化输入工具填写文本、单选框、复选框和下拉框。
5. 每次填写后验证字段值。
6. 对不确定字段调用 `ask_user`。
7. 全部填写完成后，生成摘要供用户确认。
8. 用户确认后提交表单，并验证提交结果。

### 7.4 跨页面搜索、筛选和整合信息

1. Agent 制定多阶段计划，并写入 checkpoint。
2. 按阶段打开多个标签页。
3. 分别获取页面摘要并提取关键信息。
4. 使用 `file_write` 或工作记忆保存中间结果。
5. 对不同页面信息进行整合和推理。
6. 根据整合结果执行后续操作。
7. 任务完成后更新长期记忆和 SOP。

## 8. MVP 里程碑

| 里程碑 | 目标 | 验收要点 |
| --- | --- | --- |
| M1 | 插件基础框架 + Side Panel + 本地服务通信 | 插件可加载，Side Panel 可输入任务，本地 Agent 可收到消息 |
| M2 | 标签页管理和页面快照 | 可获取标签页列表，可返回结构化页面摘要 |
| M3 | 结构化浏览器动作与人工确认 | 支持点击、输入、滚动、切换标签页和 `ask_user` |
| M4 | 跑通 B 站和 Google Scholar 示例 | 完成两个端到端任务，具备失败重试能力 |
| M5 | 表单填写、跨页面任务和记忆/SOP | 支持复杂表单填写，跨页面整合，并能沉淀技能 |

## 9. 验收标准

- 能够完成题目中的示例任务，且不依赖针对特定网站写死的脚本。
- 系统具备浏览器感知、动作执行、结果验证和异常恢复能力。
- 支持任务中断、人工确认和用户停止。
- 关键浏览器动作有日志和页面变化验证。
- 长任务状态可以恢复，不因插件 Service Worker 终止而丢失。
- 文档结构完整，可作为后续实现、评审和测试依据。

## 10. 风险与应对

| 风险 | 应对 |
| --- | --- |
| Chrome Web Store 审核风险 | 遵循最小权限原则，清晰说明用途，避免不必要 `debugger` |
| 网站反自动化风险 | 优先真实浏览器会话，避免无脑 headless 特征，遇到验证码人工介入 |
| 长任务状态丢失 | 使用持久化 checkpoint，任务状态由本地 Agent 负责 |
| 本地服务分发成本 | MVP 先本地运行，产品化阶段再提供安装器和自动启动方案 |
| 模型调用成本 | 使用页面摘要、局部 DOM、SOP 记忆降低 token 消耗 |
| 多网站兼容性 | 以通用能力为主，通过技能沉淀逐步覆盖具体网站 |
